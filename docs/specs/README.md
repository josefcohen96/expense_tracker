# Feature specs

One file per feature, written by the `feature-design` skill before any code, and committed together with the implementation so the reasoning survives.

File name: `YYYY-MM-DD-<slug>.md` (English slug). The sections are fixed (see `.claude/skills/feature-design/SKILL.md`) so the `implementer` agent can rely on them: *In one line · The signature · Framings considered · Behaviour · Data · API · Files to touch · Acceptance criteria · Tests to add · Out of scope · Open questions*.

A spec is done when the "generic detector" in the skill passes: it names something only this household has, needs no "manage / track / dashboard" words, saves a tap on the phone, has a moment of relief or delight, and Yosef or Karina would notice it a week later.
